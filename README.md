# Roame Flight Explorer

Native SwiftUI (iOS) and Jetpack Compose (Android) flight explorers on one shared Kotlin Multiplatform module, plus a local flights API. You can search and filter 1,000 fixture flights, browse them as a list or on a map, save flights, and keep working offline.

- The spec is `docs/BRIEF.md`.
- Submission notes (approach, assumptions, tradeoffs, known limitations, how AI was used) are in `docs/NOTES.md`.
- QA results: Android in `docs/QA_ANDROID.md` (the owner's recorded walkthrough and the Android UI tests); iOS in `docs/QA_IOS.md` (the CI simulator, its screenshots and its walkthrough recording).

| Path | What's in it |
|---|---|
| `server/` | The local API (Ktor): `GET /flights`, `GET /health`, and modes for empty, failing, updated and slow responses |
| `shared/` | Kotlin Multiplatform: networking (Ktor), persistence (SQLDelight), search, filters, map aggregation and clustering, selection, sync state and display formatting. Both apps render one `FlightExplorerStore` |
| `androidApp/` | The Compose UI, with a MapLibre map (OpenFreeMap tiles, no API key) |
| `iosApp/` | The SwiftUI UI, with MapKit, and the XCUITests. The project is generated by XcodeGen from `iosApp/project.yml`, and the `.xcodeproj` is committed |
| `fixtures/flights.json` | The 1,000 flights |

## Download instead of building
Each tagged release (`v*`) on the repository's Releases page has the API as one jar (plus a Python fallback), the Android debug APK and the iOS simulator app. `QUICKSTART.md` explains how to run them, and why the simulator app can't go on a physical iPhone.

## Prerequisites
- **JDK:** Gradle selects or downloads JDK 25 itself. Android Studio's bundled JDK is enough to launch it.
- **Android:** Android Studio (Quail 3 or newer) with SDK Platform 37.0 and build-tools 37.0.0, plus an emulator.
- **iOS:** a Mac with Xcode 26.4 (CI uses 26.4.1) and an iPhone simulator. Xcode's build phase runs Gradle, so it also needs a JDK; it finds Android Studio's automatically.
- First builds need internet access.

## Run the local API
From the repository root:

```sh
./gradlew :server:run          # macOS / Linux
gradlew.bat :server:run        # Windows
```

It serves `http://localhost:8080/flights` and `/health`. Optional arguments go in `--args="…"`:

| Argument | Effect |
|---|---|
| `--mode=normal` | The fixture, byte for byte (the default) |
| `--mode=empty` | 200 with no flights |
| `--mode=error` | 500 |
| `--mode=updated` | Every flight costs 500 points more, to exercise "Update saved" |
| `--mode=slow` | The normal fixture, 3 s late, to show loading states |
| `--port=8080` | The port |
| `--allow-control` | Enables `POST /control/mode?value=…`, which the iOS UI tests use to switch modes |

For example: `./gradlew :server:run --args="--mode=slow"`. On Windows, allow Java through the firewall (private networks) if asked.

The same API also runs on its own:
- **One jar** with the fixture inside: `./gradlew :server:fatJar`, then `java -jar server/build/libs/roame-flights-server.jar` (Java 17+), from any directory, with the same arguments.
- **Python 3.9+ fallback** for machines without Java: `python3 server/fallback.py` (Windows: `py server\fallback.py`), with the same arguments.

## Run the Android app
1. Start the API.
2. Open the repository in Android Studio and run `androidApp` on an emulator, or run `./gradlew :androidApp:installDebug`.
   - The app's default base URL is `http://10.0.2.2:8080`, which is how the emulator reaches the computer running it.
   - For another address, build with `-PapiBaseUrl=http://<host>:8080`.
   - For a phone on USB, or an emulator that can't reach `10.0.2.2`, use `http://localhost:8080`. Build with `-PapiBaseUrl=http://localhost:8080`, or add `apiBaseUrl=http://localhost:8080` to `~/.gradle/gradle.properties` (Windows: `%USERPROFILE%\.gradle\gradle.properties`) so Android Studio's Run uses it too.
     - Each debug build then runs `adb reverse tcp:8080 tcp:8080` on every connected device, so the device's `localhost:8080` reaches this computer.
     - The forward lasts until the device restarts. After that, build or Run again.
3. Debug builds have a menu (⋮ in the top bar) that simulates save and remove failures.

## Run the iOS app
1. Start the API.
2. Open `iosApp/RoameStarter.xcodeproj` in Xcode, choose the `RoameStarter` scheme and an iPhone simulator, and run. The first build compiles the shared Kotlin framework through Gradle, which takes a few minutes.
   - The simulator reaches the Mac as `localhost`, the default base URL (`API_BASE_URL` in `iosApp/RoameStarter/Info.plist`).
   - To use another address, add the launch argument `-apiBaseUrl http://<host>:8080` (Edit Scheme → Run → Arguments).
   - Debug launch arguments: `-resetData` (start like a fresh install), `-failSaves`, `-failRemoves`.
   - On a physical iPhone, choose a signing team, use `-apiBaseUrl http://<your-mac>.local:8080` with both devices on the same network, and allow Local Network access when asked.
3. XcodeGen 2.46.0 is needed only after adding, removing or renaming files under `iosApp/`: run `xcodegen generate --spec iosApp/project.yml`, and commit the result.

## Use another server address
Debug builds of both apps can switch the flights server at runtime, for example to run on a phone on the same Wi-Fi as the computer running the API.
- **Android:** the debug menu (⋮ in the top bar) → Server URL….
- **iOS:** the ladybug button, top left.

Enter the computer's address, such as `http://192.168.1.20:8080`. The apps check it as you type, fetch from it on Save, and keep it across launches. "Use default" goes back to the build's address. On a device, allow Local Network access when asked.

## Tests

| What | Command |
|---|---|
| Server | `./gradlew :server:test` |
| Shared logic on the JVM: filters, search, date and points boundaries, map aggregation and clustering, camera fit, persistence, sync and failure handling | `./gradlew :shared:testAndroidHostTest` |
| Shared logic on the iOS simulator (Mac with Xcode) | `./gradlew :shared:iosSimulatorArm64Test --device "<simulator UDID>"` |
| Android build | `./gradlew :androidApp:assembleDebug` |
| Android UI tests on an emulator: launch, search, filters, map selection, save, then a relaunch with the API stopped | Build `:androidApp:assembleDebug :androidApp:assembleDebugAndroidTest :server:fatJar`, start the jar as in `.github/workflows/android-ui.yml`, then run `.github/scripts/android-ui-tests.sh` (see the comment at its top) |
| iOS UI tests (XCUITest) | Start the API with `--allow-control`, then Product → Test in Xcode. `DemoWalkthrough` and `OfflineRelaunchTests` expect the API to be stopped between them, as in `.github/workflows/ios.yml`, so skip them in a local run |

CI runs all of it on pull requests and pushes to `main` that change code (docs-only changes skip it):
- `.github/workflows/ci.yml` (Linux): server tests, shared tests, Android build.
- `.github/workflows/android-ui.yml` (Linux): the Android UI tests on an API 36 emulator, against the running API. Its `android-ui-tests` artifact has the results, logcat and any failure screenshots, and `android-demo` has `android-demo.mp4`: a slow walkthrough, then a relaunch with the API stopped.
- `.github/workflows/ios.yml` (macOS): the build and the shared tests on the simulator, then XCUITests against the running API.
  - Pull requests run 5 smoke tests: launch, search, map selection, save, error state.
  - Pushes to `main` and manual runs (workflow_dispatch) run the full suite, then the offline relaunch with the API stopped.
  - Its `ios-ui-tests` artifact has the result bundles and screenshots, and on full runs a demo video.

## Troubleshooting
- **Android says "Couldn't load flights".** Either the API isn't running, or the app can't reach it.
  - The API logs every request. If Retry adds no `GET /flights` line, the app's requests aren't reaching it.
  - The emulator reaches the computer as `10.0.2.2`, the default. If it can't, while `http://localhost:8080/health` works on the computer, use the `localhost` setup in "Run the Android app".
  - Release builds allow plain HTTP only to `10.0.2.2`, `localhost` and `127.0.0.1` (`androidApp/src/main/res/xml/network_security_config.xml`). Debug builds allow it to any host.
- **iOS can't connect.** Plain HTTP works because `Info.plist` sets `NSAllowsLocalNetworking`, which covers `localhost` and `.local` names. Any other host needs its own App Transport Security exception.
- **Xcode shows "No such module 'Shared'" before the first build.** Build once (⌘B). The error clears once Gradle has produced the framework.
- **The iOS link fails on files under `shared/build/skie/…/swift-generated-sources`.** Delete `shared/build/skie` and build again (SKIE issue #208).
- **Xcode's "Build shared Kotlin framework" phase can't find Java.** Install Android Studio, or set `JAVA_HOME`.
